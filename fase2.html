HARI 31 Arsitektur IoT & Instalasi Eclipse Mosquitto MQTT Broker
BLOK 1 (2 Jam) — Teori & Instalasi Mosquitto di Ubuntu Server
  1. Pahami alur Publisher (Sensor) → Broker (Server) → Subscriber (Dashboard/DB) serta hierarki topik seperti pln/gardu01/meter01/daya.
  2. Instal paket broker dan klien Mosquitto di server Ubuntu:
bash — Ubuntu Server
sudo apt update && sudo apt install -y mosquitto mosquitto-clients
sudo systemctl enable --now mosquitto
sudo systemctl status mosquitto
BLOK 2 & 3 (4 Jam) — Eksperimen Publish/Subscribe & QoS
  1. Buka 2 tab terminal SSH ke server. Di Terminal 1, dengarkan semua topik menggunakan wildcard #:
bash — Terminal 1 (Subscriber)
mosquitto_sub -h localhost -t "smartgrid/#" -v
  1. Di Terminal 2, kirim pesan simulasi dengan QoS 1 dan flag Retained (-r) agar pesan terakhir tersimpan di broker:
bash — Terminal 2 (Publisher)
mosquitto_pub -h localhost -t "smartgrid/meter01/status" -m "ONLINE" -q 1 -r
mosquitto_pub -h localhost -t "smartgrid/meter01/volt" -m "221.5" -q 1
GOAL HARI 31: Layanan mosquitto aktif di port 1883 (cek dengan ss -tulpn | grep 1883) dan pesan retained langsung muncul saat subscriber baru terhubung.
HARI 32 Pengamanan Akses Mosquitto (Autentikasi User & ACL Topic)
BLOK 1-3 (6 Jam) — Matikan Akses Anonim & Buat File Password
  1. Buat file kredensial khusus perangkat sensor dan server backend:
bash — Buat User MQTT
sudo mosquitto_passwd -c /etc/mosquitto/passwd sensor_meter
sudo mosquitto_passwd -b /etc/mosquitto/passwd backend_server RahasiaServer123
  1. Buat file konfigurasi kustom agar broker mendengarkan koneksi jaringan luar dengan autentikasi wajib:
bash — /etc/mosquitto/conf.d/custom.conf
cat << 'EOF' | sudo tee /etc/mosquitto/conf.d/custom.conf
listener 1883
allow_anonymous false
password_file /etc/mosquitto/passwd
EOF
sudo systemctl restart mosquitto
sudo ufw allow 1883/tcp
  1. Uji coba koneksi tanpa password (harus ditolak: Connection Refused: not authorised), lalu uji ulang memakai flag -u sensor_meter -P passwordmu.
GOAL HARI 32: Broker menolak semua koneksi anonim dan hanya menerima publikasi data dari klien ber-username valid.

HARI 35-36 Proyek Simulator 5 Smart Meter & Worker Pendeteksi Anomali
Hari 35 — Buat Skrip Publisher Simulator (simulator_meter.py)
python — ~/iot-project/simulator_meter.py
import time, json, random
import paho.mqtt.client as mqtt

BROKER = "127.0.0.1"
USER = "sensor_meter"
PASS = "GantiPasswordSensor"
METERS = ["MTR-1001", "MTR-1002", "MTR-1003", "MTR-1004", "MTR-1005"]

client = mqtt.Client(mqtt.CallbackAPIVersion.VERSION2)
client.username_pw_set(USER, PASS)
client.connect(BROKER, 1883, 60)

while True:
    for m in METERS:
        volt = round(random.uniform(215.0, 232.0), 2)
        amp = round(random.uniform(1.2, 16.5), 2)
        watt = round(volt * amp, 2)
        payload = json.dumps({"meter_id": m, "voltage": volt, "current": amp, "power_w": watt})
        client.publish(f"pln/smartmeter/{m}/telemetry", payload, qos=1)
        print(f"[SENT] {m}: {payload}")
    time.sleep(3)

Hari 39 — Skrip Bridge MQTT ke InfluxDB (mqtt_to_influx.py)
python — mqtt_to_influx.py
import json
import paho.mqtt.client as mqtt
from influxdb_client import InfluxDBClient, Point
from influxdb_client.client.write_api import SYNCHRONOUS

influx = InfluxDBClient(url="http://localhost:8086", token="TEMPEL_TOKEN_DISINI", org="pln_iot")
write_api = influx.write_api(write_options=SYNCHRONOUS)

def on_message(client, userdata, msg):
    data = json.loads(msg.payload.decode())
    p = Point("electricity").tag("meter_id", data["meter_id"])         .field("voltage", float(data["voltage"]))         .field("current", float(data["current"]))         .field("power_w", float(data["power_w"]))
    write_api.write(bucket="smartmeter_db", record=p)
    print("Saved to InfluxDB:", data["meter_id"])

client = mqtt.Client(mqtt.CallbackAPIVersion.VERSION2)
client.username_pw_set("backend_server", "RahasiaServer123")
client.on_message = on_message
client.connect("127.0.0.1", 1883)
client.subscribe("pln/smartmeter/+/telemetry")
client.loop_forever()

HARI 50 Orkestrasi Seluruh Ekosistem IoT dalam 1 File docker-compose.yml
BLOK 1-3 (6 Jam) — Migrasi Kontainer Terpisah Menjadi Satu Stack
  1. Hentikan kontainer manual sebelumnya (docker stop influxdb grafana nodered && docker rm influxdb grafana nodered) namun pertahankan volume datanya.
  2. Buat file ~/iot-project/docker-compose.yml untuk menyatukan InfluxDB, Grafana, dan Node-RED dalam satu jaringan internal Docker:
yaml — ~/iot-project/docker-compose.yml
services:
  influxdb:
    image: influxdb:2.7
    container_name: iot_influxdb
    restart: unless-stopped
    ports:
      - "8086:8086"
    volumes:
      - influxdb_data:/var/lib/influxdb2

  grafana:
    image: grafana/grafana-oss
    container_name: iot_grafana
    restart: unless-stopped
    ports:
      - "3000:3000"
    depends_on:
      - influxdb
    volumes:
      - grafana_data:/var/lib/grafana

  nodered:
    image: nodered/node-red
    container_name: iot_nodered
    restart: unless-stopped
    ports:
      - "1880:1880"
    volumes:
      - nodered_data:/data

volumes:
  influxdb_data:
  grafana_data:
  nodered_data:
  1. Jalankan seluruh infrastruktur dengan satu perintah: docker compose up -d.
GOAL HARI 50: Seluruh layanan backend IoT menyala bersamaan lewat docker compose up -d dengan kebijakan restart: unless-stopped.

HARI 55 Konfigurasi Auto-Recovery Layanan Python via Systemd
BLOK 1-3 (6 Jam) — Jadikan Worker Backend Berjalan Otomatis Saat Booting
  1. Daftarkan mqtt_to_influx.py sebagai layanan sistem Linux agar langsung hidup saat server menyala ulang:
bash — /etc/systemd/system/iot-bridge.service
cat << EOF | sudo tee /etc/systemd/system/iot-bridge.service
[Unit]
Description=MQTT to InfluxDB Bridge Service
After=network.target mosquitto.service docker.service

[Service]
User=$USER
WorkingDirectory=/home/$USER/iot-project
ExecStart=/home/$USER/iot-project/venv/bin/python /home/$USER/iot-project/mqtt_to_influx.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now iot-bridge
  1. Uji coba dengan perintah sudo reboot, lalu setelah server hidup kembali pastikan seluruh layanan (Mosquitto, Docker Compose, dan iot-bridge) langsung aktif tanpa campur tangan manual.
GOAL HARI 55: Sistem IoT pulih otomatis 100% dalam waktu <30 detik setelah server di-reboot.
