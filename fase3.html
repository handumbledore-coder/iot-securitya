MINGGU 09: Pengintaian Jaringan & Eksploitasi IoT dengan Kali Linux (Hari 61 – 64)
HARI 61 // BLOK 1-3 (6 JAM)
Penyadapan Trafik MQTT (Sniffing) & Manipulasi Data (Spoofing)

BLOK 1 (2 Jam) — Pemindaian Port Layanan IoT dengan Nmap

Dari terminal Kali Linux (pastikan satu jaringan Bridge/Host-Only dengan Server Ubuntu Fase 02), pindai port terbuka pada IP server target:

nmap -sV -sC -p 22,1883,3000,8086,8883 192.168.1.100

BLOK 2 (2 Jam) — Menyadap Username, Password & Data Sensor

Tangkap paket jaringan pada port 1883 menggunakan tshark atau Wireshark untuk membuktikan komunikasi MQTT tanpa enkripsi bisa dibaca:

sudo tshark -i eth0 -f "tcp port 1883" -Y "mqtt" -V | grep -E "Topic|Message|User Name|Password"

BLOK 3 (2 Jam) — Injeksi Data Palsu (MQTT Spoofing)

Gunakan kredensial yang tertangkap untuk mengirim nilai tagihan/daya palsu ke topik Smart Meter:

mosquitto_pub -h 192.168.1.100 -p 1883 -u "meter_user" -P "rahasia123"   -t "pln/smartmeter/MTR01" -m '{"voltage": 220, "current": 0.01, "watt": 2.2, "status": "SPOOFED"}'
VERIFIKASI LULUS: Berhasil menangkap kredensial *cleartext* di Kali Linux dan memanipulasi angka grafik di dashboard Grafana.
HARI 62 // BLOK 1-3 (6 JAM)
Pengujian Kekuatan Autentikasi (Brute Force) dengan Hydra

BLOK 1-3 (6 Jam) — Simulasi Audit Password Lemah pada SSH & MQTT

Siapkan daftar kata sandi uji coba (wordlist) dan jalankan audit menggunakan Hydra di Kali Linux terhadap server lab milikmu sendiri:

mkdir -p ~/iot-audit && cd ~/iot-audit
printf "123456
admin
password
rahasia123
pln2026
" > wordlist.txt

# Uji SSH
hydra -l teknisi -P wordlist.txt ssh://192.168.1.100 -t 4

# Uji MQTT Broker
hydra -l meter_user -P wordlist.txt 192.168.1.100 mqtt
VERIFIKASI LULUS: Hydra berhasil menemukan password yang lemah serta kamu mencatat log percobaan login gagal di /var/log/auth.log server target.
HARI 63 // BLOK 1-3 (6 JAM)
Keamanan Nirkabel IoT: Pemindaian Wi-Fi & Bluetooth Low Energy (BLE)

BLOK 1-3 (6 Jam) — Eksplorasi Perangkat BLE & Jaringan Nirkabel

Pelajari cara mendeteksi perangkat IoT berbasis Bluetooth Low Energy di sekitar menggunakan utilitas Linux:

# Cek adaptor Bluetooth & pindai perangkat BLE
hciconfig
sudo timeout 15s hcitool lescan

# Atau gunakan bluetoothctl interaktif
bluetoothctl
# Di dalam prompt bluetoothctl:

# info [MAC_ADDRESS]

Pelajari juga konsep *monitor mode* Wi-Fi (airmon-ng) dan identifikasi enkripsi lemah (WEP/WPA2-PSK) pada *gateway* IoT.

VERIFIKASI LULUS: Memahami pemetaan karakteristik GATT pada BLE serta mengetahui perbedaan keamanan WPA2 vs WPA3 untuk jaringan IoT.

MINGGU 10: Analisis Firmware & Pengerasan Sistem (Hardening) (Hari 65 – 71)
HARI 65 – 67 // 3 HARI (18 JAM)
Ekstraksi & Audit Keamanan Firmware IoT dengan Binwalk

Hari 65-66 — Membongkar File Binary Firmware

Unduh sampel firmware open-source (misal image router OpenWrt atau sampel latihan DVRF) di Kali Linux, lalu ekstrak sistem file SquashFS di dalamnya:

sudo apt update && sudo apt install -y binwalk squashfs-tools
mkdir -p ~/firmware-lab && cd ~/firmware-lab

# Analisis struktur firmware & ekstrak isinya
binwalk firmware_sample.bin
binwalk -e firmware_sample.bin

Hari 67 — Mencari Kredensial Hardcoded & Kunci Privat

Masuk ke folder hasil ekstraksi (_firmware_sample.bin.extracted/squashfs-root) dan cari potensi kebocoran rahasia:

cd _*.extracted/squashfs-root
cat etc/passwd
cat etc/shadow
grep -rnw . -e "password" -e "api_key" -e "BEGIN RSA PRIVATE KEY" 2>/dev/null | head -n 30
VERIFIKASI LULUS: Berhasil mengekstrak struktur root filesystem dari file .bin dan menemukan file konfigurasi sensitif di dalamnya.
HARI 68 – 69 // 2 HARI (12 JAM)
Mengamankan Komunikasi IoT dengan MQTTS (TLS/SSL Port 8883)

Hari 68 — Membuat Sertifikat CA & Server SSL dengan OpenSSL

Di Server Ubuntu, buat sertifikat TLS agar seluruh data Smart Meter terenkripsi penuh:

mkdir -p ~/iot-certs && cd ~/iot-certs
# 1. Buat Certificate Authority (CA)
openssl genrsa -out ca.key 2048
openssl req -new -x509 -days 365 -key ca.key -out ca.crt -subj "/CN=SmartGrid-CA"

# 2. Buat Kunci & Sertifikat Server MQTT
openssl genrsa -out server.key 2048
openssl req -new -key server.key -out server.csr -subj "/CN=192.168.1.100"
openssl x509 -req -in server.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out server.crt -days 365

Tambahkan konfigurasi listener terenkripsi ke mosquitto.conf dan tutup port 1883 dari akses luar:

listener 8883
cafile /mosquitto/certs/ca.crt
certfile /mosquitto/certs/server.crt
keyfile /mosquitto/certs/server.key
allow_anonymous false

Hari 69 — Verifikasi Enkripsi Menggunakan Wireshark

Kirim pesan uji memakai --cafile ca.crt di port 8883, lalu tangkap ulang trafiknya dari Kali Linux:

mosquitto_pub -h 192.168.1.100 -p 8883 --cafile ca.crt   -u "meter_user" -P "StrongPass#2026" -t "pln/smartmeter/MTR01" -m '{"watt": 450}'
VERIFIKASI LULUS: Di Wireshark Kali Linux, paket kini tampil sebagai protokol TLSv1.3 Application Data terenkripsi dan tidak ada lagi password maupun JSON yang terbaca.
HARI 70 // BLOK 1-3 (6 JAM)
Proteksi Blokir Otomatis Serangan Brute Force dengan Fail2Ban

BLOK 1-3 (6 Jam) — Instalasi & Konfigurasi Jail Fail2Ban

Pasang Fail2Ban di Ubuntu Server agar IP penyerang otomatis diblokir setelah 3 kali gagal login:

sudo apt update && sudo apt install -y fail2ban
sudo cp /etc/fail2ban/jail.conf /etc/fail2ban/jail.local

# Aktifkan & cek status pemblokiran
sudo systemctl enable --now fail2ban
sudo fail2ban-client status sshd

Uji coba dengan melakukan serangan Hydra ulang dari Kali Linux dan pastikan IP Kali otomatis masuk daftar Banned IP list.

VERIFIKASI LULUS: IP Kali Linux terblokir otomatis oleh firewall server dalam hitungan detik saat menjalankan serangan brute force.

HARI 81 – 84 // 4 HARI (24 JAM)
Latihan Wawancara Teknis & Ujian Live Troubleshooting 60 Menit

Hari 81-83 — Latihan Pertanyaan Wawancara Teknis Wajib

  • Disk Penuh padahal df -h masih ada sisa? Jelaskan konsep Inodes penuh (cek dengan df -i) atau file terhapus yang masih dikunci proses berjalan (lsof +L1).
  • Perbedaan TCP vs UDP pada IoT? TCP menjamin pengiriman paket berurutan (dipakai MQTT/HTTPS), sedangkan UDP lebih ringan tanpa *handshake* (dipakai DNS/CoAP).
  • Cara mengamankan server Linux baru? Update sistem, buat user non-root dengan sudo, matikan login password SSH (pakai SSH Key), aktifkan firewall UFW, dan pasang Fail2Ban.

Hari 84 — Simulasi Ujian Praktik Darurat (60 Menit)

VERIFIKASI LULUS: Mampu menjelaskan konsep teknis dengan bahasa lugas dan menyelesaikan skenario kerusakan server secara sistematis.
